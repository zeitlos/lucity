Welcome to Lucity. This guide will walk you through how you can deploy your first app to Lucity and access it via a magical thing called the internet.

Before we can get started, make sure you have an account for GitHub. If you don't already have once, you can sign up [here](https://github.com/signup) for free.

So let's get started!

## 1. Create Account

If you haven't already, make sure to creat a Lucity account by signing in with your GitHub account. [Click here](https://lucity.cloud/app/login). Lucity is free to use for the first 14 days or €5 of credits spent without having to connect your credit card.

## 2. Fork example Repo

For this guide we prepared an example app. It's called Vouch and is [publicly available on GitHub](https://github.com/zeitlos/vouch). Take a look at the code and you'll see that this is a simple feedback board app using Next.js. Feedbacks are stored in a PostgreSQL and an optional obejct storage bucket allows users to upload attachments. Note that there is also no Dockerfile in the repo. Lucity builds apps directly from source, without requiring a Dockerfile. Learn more about builds here. (TODO: add link)

If you want to follow along with the tutorial, make sure you fork the Vouch repo to your own account. This essentially creates a copy of the code on your account.

## 3. Create a new Project

Go to the Lucity dashboard project overview, click "New" and select "GitHub Repository" from the command palette that opened. Then select the vouch repository in the next screen (note that you might have to change to the correct organization). After confirming the project and service name you will be taken to the project canvas where the newly created service is being built.

## 4. Build + Deploy

If you click on the service, you can watch the build and deploy process in real time and read the corresponding logs. Usually this takes about 2 - 3 minutes. Once the build + deploy is finished, the service status will show as "Online" and you can read the logs of the build + deploy by clicking on the active deployment within the service panel.

## 5. Expose it via Platform Domain

Now we have a deployed service but no way of accessing it. Let's change that by adding a free public domain to it. Click on the service then navigate to the settings tab within the service panel. Scroll down to "Platform Domain" and click "Generate Domain". Once the operation completes, you will see a domain similar to "vouch-development-xxxxx.lucity.app". Click on it and you will see the interface of the demo app. Congrats, you just deployed and exposed your first app via Lucity!

But as you might also see in the Vouch interface it says "Database not connected". So let's take care of that.

## 6. Connect Database

Back in the Lucity project canvas click the "Create" button, select "PostgreSQL" and enter a name. Let's call the database "posts" and click "Create Database". A new database card will appear on the canvas with the status "provisioning".

To now connect this new database to Vouch, click on the on the vouch service card and navigate to the "Variables" tab. Click "Add Variable" and enter "DATABASE_URL" as the key. Select the link icon in the value field, select "fqdn-uri" from the dropdown and hit save. We just created what we call a "dynamic variable". Learn more about dynamic variables in the variable docs (TOOD: add link). This will restart the vouch service with a environment variable set to the connection string of the posts database.

If we now reload the vouch application the database connection warning is gone and we can add posts to the feedback board. Add a couple of posts, then go back to the dashboard, click on the database and select the "Tables" tab. Select the "posts" table and you will see the feedback posts you just created within Vouch. Nice!

## 7. Connect Object Storage Bucket

Vouch also supports attaching images to posts. To enable that feature we have to configure an object storage bucket. On the canvas click "Create" then select "Bucket" and name it and create the bucket. The bucket appears along the service and database on the canvas. Now we can wire up all object storage related variables: `S3_ACCESS_KEY_ID`, `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_SECRET_ACCESS_KEY` hit save and reload the application. Now when we submit a post a new "attach image" input appears. Upload an image and submit it, then go back to the dashboard and click on the bucket card. In the files tab you'll see an upload directory with the image inside it.
